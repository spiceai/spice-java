# Spice Java SDK v0.8.1

## Fixes

### 🔑 Fewer restrictions on the API key field for self-managed runtimes

`SpiceClientBuilder.withApiKey()` now has fewer restrictions on the API key value. Before, the key had to use the Spice Cloud format `appId|secret`. Now the client accepts any value that is not empty. Thus you can connect to a self-managed Spice runtime that has [API key authentication](https://spiceai.org/docs/api/auth) enabled. Before, a key for a self-managed Spice runtime failed with `IllegalArgumentException: apiKey is invalid`, and the only workaround was the multi-argument `SpiceClient` constructor with a made-up app ID. ([#60](https://github.com/spiceai/spice-java/pull/60))

```java
try (SpiceClient client = SpiceClient.builder()
        .withApiKey("my-runtime-key")
        .build()) {
    // ...
}
```

- When the key does not use the `appId|secret` format (the usual case for a self-managed Spice runtime), the key goes out as `Authorization: Bearer <key>` on each Flight call: `sql()`, `sqlWithParams()` and Flight actions. There is no handshake.
- A key that the runtime rejects fails at once with `UNAUTHENTICATED`. The client does not retry it, and does not prepare a cached statement again with the same key.
- A Spice Cloud key (`appId|secret`) continues to use the Basic handshake, and gets a new session token when the old one expires, as before.
- If you used the constructor workaround, it continues to work.
